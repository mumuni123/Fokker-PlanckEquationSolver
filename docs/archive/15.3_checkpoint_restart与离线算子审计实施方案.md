# 15.3 checkpoint/restart 与离线算子审计实施方案

## 1. 目的与结论

本方案用于建立第 15.3 节 A/B/C/D 诊断所需的基础设施，包括：

1. 完整物理状态 checkpoint/restart；
2. 按接受步停止和按物理时间停止；
3. `dt-scale` 控制；
4. 中点最大迭代次数控制；
5. 最终中点试探状态保存；
6. 固定同一中点状态、调用生产离散算子的只读审计模式；
7. 每组实验使用独立输出目录。

原有方向基本正确，但仍有以下关键缺漏，必须同时补齐：

- checkpoint 必须有版本、网格、MPI 拓扑和参数一致性校验；
- Beam 的私有持久状态必须通过正式导入/导出接口保存，不能只保存粒子数组；
- 写检查点必须采用“rank 临时文件全部成功后再提交 manifest”的原子协议；
- 重启后不能再次解初始 Poisson，否则会覆盖已经由 Ampere 演化的场；
- `--stop-after-steps` 必须统计真实接受步，不是 trial 或中点迭代次数；
- `dt/2` 实验必须保持同一物理时间区间，并让 Beam 注入按两个真实半步分别发生；
- C 测试不能复写一份简化公式，必须调用生产求解器实际使用的通量、FCT、`G/G*` 和电流构造代码；
- 仅保存 `f_mid/E_mid` 不足以严格复现 FCT 后的 `JN/JE`，还必须保存步初态、最终端点猜测、子步数和离散开关；
- 所有输出路径必须统一受 `--output-dir` 控制，不能继续存在硬编码 `output/...`。

本次只建立诊断基础设施，不改变 Vlasov、FCT、Beam pusher、轨迹沉积和 Ampere 的物理推进。

---

## 2. 不可改变的物理与离散部分

实现过程中不得修改：

- Yee face 上的 `Ex_face/Jx_face` Ampere 推进；
- 背景 `advect_x`、速度空间受力和 FCT 的生产通量定义；
- Beam 注入、开放出流、轨迹电流沉积；
- 周期场 ghost 同步方式；
- `JN`、`JE`、`G/G*` 的生产定义；
- 中点方程和当前严格/软接受准则；
- 每步净电荷、场零模或 Poisson 投影策略。

checkpoint 和审计模式必须是旁路基础设施。关闭这些功能后，生产结果应与修改前保持逐位一致或仅有输出顺序造成的非物理差别。

## 4. 运行参数

### 4.1 参数结构

在 `runtime_options.h` 中增加：

```cpp
struct RuntimeOptions {
    std::string output_dir;
    std::string restart_dir;
    std::string operator_audit_dir;
    std::vector<double> checkpoint_times_fs;

    double stop_time_fs;
    long long stop_after_accepted_steps;
    double dt_scale;
    int midpoint_max_iters;
    int diagnostic_level;

    bool dump_final_midpoint;
    bool overwrite_output;
    bool checkpoint_enabled;
    bool restart_enabled;
    bool operator_audit_mode;
};
```

默认值必须完全保持当前生产行为：

```text
output_dir                 = output
restart                    = disabled
checkpoint_times           = empty
stop_time_fs               = Param::t_end / fs
stop_after_accepted_steps  = -1
dt_scale                   = 1.0
midpoint_max_iters         = 40
diagnostic_level           = 1
dump_final_midpoint        = false
operator_audit             = disabled
```

### 4.2 命令行

支持：

```text
--restart <checkpoint_dir>
--checkpoint-times <3,6,12>
--stop-time-fs <value>
--stop-after-steps <accepted_step_count>
--midpoint-max-iters <count>
--dt-scale <value>
--diagnostic-level <0|1|2>
--output-dir <dir>
--dump-final-midpoint
--operator-audit <midpoint_audit_dir>
--overwrite-output
```

要求：

1. 未识别参数必须报错并在所有 rank 一致退出；
2. rank 0 解析后广播给全部 rank，或每个 rank 解析后用哈希验证完全一致；
3. `dt_scale>0`，`midpoint_max_iters>=1`；
4. `--operator-audit` 与正常时间推进互斥；
5. 非空输出目录若已存在且包含结果，默认拒绝运行；只有显式 `--overwrite-output` 才允许清空或覆盖；
6. A/B/C/D 必须使用不同输出目录，禁止追加到同一个 `step_diagnostics.dat`。

### 4.3 统一输出根目录

当前所有：

```cpp
"output/..."
diag.init("output", ...)
```

必须改为从 `RuntimeOptions::output_dir` 生成路径。新增统一函数：

```cpp
std::string output_path(const RuntimeOptions& opts,
                        const std::string& filename);
```

不得只修改 `Diagnostics::init()`，因为 `main.cpp` 和求解器中仍存在直接打开审计文件的路径。

## 5. checkpoint 数据模型

## 5.1 目录协议

每个 checkpoint 使用独立目录：

```text
checkpoints/
  t_03.000000fs_step_00002249/
    manifest.dat
    rank_000000.bin
    rank_000001.bin
    ...
```

目录名中的时间只是便于阅读。重启必须以文件头中的真实 `time` 和 `step` 为准。

第一版只支持相同 MPI rank 数和相同一维分区重启。若不一致，应明确拒绝，不允许静默重新分区。

## 5.2 manifest

`manifest.dat` 至少保存：

```text
format_magic
format_version
endianness_tag
sizeof_double
sizeof_uint64
mpi_size
nx
nghost
Nv
Nmu
Lx
dx
velocity_grid_hash
physics_parameter_hash
step
time_s
dt_s
rank_file_count
每个 rank 文件的字节数和校验值
```

`physics_parameter_hash` 至少覆盖：

- 电荷、质量、背景密度和温度；
- Beam 参数和宏粒子权重；
- 空间、速度网格参数；
- FCT、high-order、low-order 配置；
- 边界条件拓扑；
- 编译期 `Nv/Nmu`。

Git 信息可以作为说明字段，但不能作为重启成功与否的硬条件。测试机没有 Git 环境时应写 `unknown`。

## 5.3 rank 二进制文件头

在 `checkpoint.h` 定义固定宽度 POD 文件头，不直接把含 `std::vector` 的类对象写入文件：

```cpp
struct RankCheckpointHeader {
    char magic[16];
    unsigned int version;
    unsigned int endian_tag;
    int mpi_rank;
    int mpi_size;
    int ix_start;
    int nx_local;
    int nx_total;
    int nghost;
    int nv;
    int nmu;
    long long step;
    double time_s;
    double dt_s;
    unsigned long long f_count;
    unsigned long long ex_face_count;
    unsigned long long beam_particle_count;
};
```

禁止使用：

```cpp
out.write(reinterpret_cast<const char*>(&species), sizeof(Species));
```

因为这些类含有 `std::vector`、字符串和指针。

## 5.4 背景电子状态

保存每个 rank 拥有的物理 x cells 中完整柱坐标质量分布：

```text
bkg_e.f[(nghost + ix), j, k]
ix = 0 ... nx_local-1
```

推荐不保存 ghost cells。重启后调用生产使用的周期 ghost 交换重新构造 ghost，从而避免把过时 ghost 当成独立状态。

不需要保存：

- `f_tmp`；
- `number_density`；
- `charge_density`；
- `current_x/current_face_x`；
- 中点求解器工作数组。

这些量必须由恢复后的 `f` 和下一次生产算子重新计算。

## 5.5 场状态

保存每个 rank 真正拥有的唯一 `Ex_face` 自由度。不要把周期 ghost face 当作第二个独立物理自由度保存。

重启后：

1. 恢复 owned `Ex_face`；
2. 调用生产场 ghost 同步；
3. 调用 `sync_cell_ex_from_faces()` 重建 `Ex`；
4. 根据恢复后的背景和 Beam 密度重建 `rho`；
5. `phi` 可按诊断需要重新计算。

严禁在 restart 路径调用：

```cpp
fields.solve_poisson(...);
```

Poisson 只用于全新初态。重启时调用它会覆盖 Ampere 已经演化出的 `Ex_face`。

## 5.6 Beam 持久状态

仅保存 `beam.particles` 不足以精确继续注入。必须在 `beam_pic.h` 中新增正式状态结构：

```cpp
struct BeamPersistentState {
    double injection_remainder;
    double cumulative_injected_energy;
    double cumulative_outflow_energy;
    double last_injected_energy;
    double last_outflow_energy;
    double last_injected_number;
    double last_outflow_number;
    double last_injected_current;
    double last_outflow_current;
    double last_field_work;
    unsigned long long rng_state;
};
```

并新增：

```cpp
BeamPersistentState BeamPIC::export_persistent_state() const;
void BeamPIC::import_persistent_state(const BeamPersistentState& state,
                                      const SpatialGrid& sg);
```

如 `begin_step()` 不会无条件重置以下量，也必须纳入持久状态：

- `step_dt_`；
- interval 注入/左右出流计数；
- 其他影响下一次注入或轨迹沉积的标量。

以下属于临时工作区，不应序列化：

- `send_left_/send_right_/recv_*`；
- `thread_*` 数组；
- `keep_` 和 offset 工作区；
- 临时轨迹密度数组。

`import_persistent_state()` 应先由 `beam.init(sgrid)` 建立正确容量，再恢复粒子和持久标量，并清空所有临时工作区。

checkpoint 只允许在完整接受步结束后写出。此时不得存在未完成的注入区间或跨 rank 粒子交换。

## 5.7 主循环持久状态

除物理状态外，还需保存：

- `step`；
- `time`；
- 基础 `dt`；
- `next_snapshot`；
- `last_snapshot_step` 或等价输出调度状态；
- `cumulative_collision_energy_delta`；
- 其他会进入累计物理能量账的标量。

不必保存纯显示统计，例如已写出的行数。但重启输出必须进入新的 `output-dir`，避免重复编号和追加污染。

## 6. checkpoint 写入与提交协议

### 6.1 原子写入

每个 rank 按以下顺序写：

```text
rank_000123.bin.tmp
写 header
写背景物理 cells
写 owned Ex_face
写 BeamPersistentState
写 BeamParticle 数组
flush + close
计算文件字节数和校验值
rename 为 rank_000123.bin
```

之后：

1. 每个 rank 产生 `local_success`；
2. `MPI_Allreduce(MPI_MIN)` 得到 `global_success`；
3. 任一 rank 失败时，不写正式 manifest，并让全部 rank 一致报错退出；
4. 全部 rank 成功后，rank 0 写 `manifest.dat.tmp`；
5. rank 0 校验所有 rank 文件存在且尺寸正确；
6. 最后 rename 为 `manifest.dat`；
7. 只有存在正式 manifest 的目录才视为可重启 checkpoint。

不要先写 manifest，再写 rank 文件。否则作业中断会留下看似完整、实际缺 rank 的检查点。

### 6.2 校验

第一版至少实现 64 位 FNV-1a 或 CRC64 校验。重启时检查：

- 文件头 magic/version；
- 文件尺寸；
- 校验值；
- rank 和分区；
- 参数哈希；
- 数组长度；
- 所有关键 double 为有限值。

任一 rank 校验失败后必须 collective 退出，不能让部分 rank 进入求解循环、部分 rank 停在读文件阶段。

## 7. restart 恢复顺序

在 `main.cpp` 中将初始化分成 `fresh_start` 和 `restart_start` 两条明确路径。

### 7.1 fresh start

保持当前逻辑：

```text
初始化网格
初始化 Maxwellian
初始化 Beam
初始化场
沉积初始密度
解一次初始 Poisson
写初始输出
```

### 7.2 restart start

严格按以下顺序：

```text
初始化网格和各类容器
读取 manifest 并校验参数/MPI分区
读取本 rank 物理 f
读取 owned Ex_face
读取 Beam 粒子与 BeamPersistentState
交换背景 f 的周期 ghost
同步 Ex_face ghost
由 face 重建 cell Ex
重新计算背景 moments
重新沉积 Beam density
重新构造 rho
恢复 step/time/dt/累计量
进行 restart 一致性审计
进入下一真实物理步
```

restart 路径不得：

- 重新初始化 Maxwellian 覆盖恢复后的 `f`；
- 重新生成 Beam 粒子；
- 重置 RNG；
- 调用 Poisson 覆盖 `Ex_face`；
- 把 `time` 重置为 0；
- 把累计注入/出流能量清零。

### 7.3 恢复后审计

进入下一步前输出一个小型 `restart_audit.dat`：

```text
step time dt
global_N_bkg
global_KE_bkg
global_beam_count
global_beam_weight
global_KE_beam
field_energy
max_abs_Ex
hash_f
hash_particles
hash_Ex_face
```

这些量必须与 checkpoint manifest 中保存的参考值一致。

## 8. checkpoint 触发和停止语义

### 8.1 checkpoint 触发

checkpoint 只能在以下顺序之后触发：

```cpp
bkg_e = midpoint_result.species_np1;
beam = midpoint_result.beam_np1;
fields = midpoint_result.fields_np1;
assert(midpoint_result.state_advanced == 1);
```

对于 `--checkpoint-times 3,6,12`，当真实接受态第一次满足：

```text
time >= target_time
```

时写出检查点，并在 manifest 中记录实际时间。不要为精确命中整数 fs 临时改变生产 `dt`。

### 8.2 单步停止

`--stop-after-steps N` 的计数器从 restart 后开始，只在：

```cpp
midpoint_result.state_advanced == 1
```

时加一。trial、中点迭代、失败重试和子循环均不计数。

达到 N 后，先完成接受态诊断和可选 midpoint dump，再正常关闭文件并 `MPI_Finalize()`。不得用 `MPI_Abort()` 实现正常停止。

### 8.3 stop-time

`--stop-time-fs T` 表示在第一个满足 `time>=T` 的接受态后正常停止。第一版不要缩短最后一个生产时间步来精确命中 T。

### 8.4 dt-scale

正常生产：

```cpp
dt = checkpoint_dt * dt_scale;
```

要求：

- A/B/C 使用 `dt_scale=1`；
- D 使用 `dt_scale=0.5`，并推进两个接受步；
- 两个 `dt/2` 步的总物理时间必须等于 A 的一个 `dt`；
- Beam 必须在两个真实半步中各自按照通量和真实 crossing time 注入；
- 不得先按完整 `dt` 注入，再把 pusher 分成两半；
- 碰撞关闭时仍保持现有关闭状态；若未来启用碰撞，也必须按两个半步真实调用。

## 9. 最终中点状态保存

## 9.1 为什么不能只保存 `f_mid/E_mid`

当前生产中点状态由：

```text
f_mid = 0.5 * (f_n + guess_np1)
E_mid = 0.5 * (E_n + E_end_guess)
```

构造。但 FCT 后的最终 `JN/JE` 还依赖：

- 步初 `f_n`；
- 最终端点猜测 `guess_np1`；
- `dt` 和真实 `nsub`；
- low/high/FCT 开关；
- 生产网格和 ghost 状态；
- 最终 Beam 中点轨迹电流（若审计总 Ampere 更新）。

因此 `--dump-final-midpoint` 应保存一个完整的审计包，而不是单独两个数组。

## 9.2 MidpointAuditState

在 `vlasov_ampere_midpoint.h` 中新增只在诊断模式使用的结构：

```cpp
struct MidpointAuditState {
    long long step;
    double time_s;
    double dt_s;
    int substeps_used;
    int nonlinear_iterations;

    bool low_order_only;
    bool high_order_enabled;
    bool fct_enabled;

    Species bkg_n;
    Species guess_np1;
    EMFields fields_n;
    EMFields fields_end_guess;

    std::vector<double> j_beam_face_mid;
    std::vector<double> reference_jn_face;
    std::vector<double> reference_je_cell;
    std::vector<double> reference_gstar_je_face;
};
```

实际写文件时仍按数组字段序列化，不能直接写含 `std::vector` 的对象内存。

为控制生产内存和 I/O：

- 默认不构造该结构；
- 仅在 `diagnostic_level=2 && dump_final_midpoint=true` 时保存；
- 只保存最后一次有限、被接受或被明确选作 B 最严格状态的迭代；
- 文件头必须注明该状态是 `strict_converged`、`soft_accepted` 还是 `unconverged_best_trial`。

若 B 在 200 次后仍未收敛，不得伪装成接受态。可以保存 `unconverged_best_trial` 供 C 做固定状态审计，但不能推进时间。

## 10. 固定状态生产算子审计

## 10.1 必须重构生产算子，而不是复写公式

当前 `advance_cylindrical_single_step()` 较长，通量构造、FCT、`JN/JE`、Ampere 和残差计算耦合在同一函数中。为了执行 C，需将“一次固定 midpoint 候选的算子评估”提取为生产共享函数，例如：

```cpp
struct MidpointOperatorEvaluation {
    Species endpoint_candidate;
    std::vector<double> jn_face;
    std::vector<double> je_cell;
    std::vector<double> gstar_je_face;
    std::vector<double> final_x_flux;
    std::vector<double> final_u_flux;
    double r_fv;
    double r_couple;
    std::array<CouplingRegionDiagnostics, 6> regions;
};

MidpointOperatorEvaluation evaluate_fixed_midpoint_operator(
    const Species& bkg_n,
    const Species& guess_np1,
    const EMFields& fields_n,
    const EMFields& fields_end_guess,
    const SpatialGrid& sg,
    double dt,
    int substeps,
    int mpi_rank,
    int mpi_size) const;
```

生产中点迭代和 C 审计必须调用这个同一个函数。禁止在 `tests/` 或 `checkpoint.cpp` 中重新写 donor、MUSCL、FCT 或 `JE` 公式。

提取函数时不得改变：

- 循环顺序；
- FCT alpha/beta 计算；
- ghost 交换时机；
- MPI owner/face 协议；
- 浮点归约类型；
- Beam predictor 时序。

第一阶段可先原样搬移代码块，并用回归测试确认生产结果不变，再做审计接口；不要在同一提交中顺便重构算法。

## 10.2 operator-audit 模式

运行：

```text
fp_solver --operator-audit <midpoint_audit_dir> \
          --output-dir <audit_output>
```

该模式必须：

1. 初始化 MPI 和相同网格；
2. 读取并校验 `MidpointAuditState`；
3. 调用一次 `evaluate_fixed_midpoint_operator()`；
4. 输出重算的 `JN`、`JE`、`G*JE` 和六区域残差；
5. 与 dump 中 reference arrays 比较；
6. 不注入 Beam；
7. 不 push Beam；
8. 不执行 Ampere 时间推进；
9. 不修改或接受任何物理状态；
10. 正常退出。

输出至少包含：

```text
max_abs_recomputed_JN_minus_reference
max_abs_recomputed_JE_minus_reference
max_abs_recomputed_GstarJE_minus_reference
R_FV
R_couple
各区域 sum_rJ/sum_abs_rJ/Linf_rJ
各区域 sum_rK/sum_abs_rK/Linf_rK
三个区域加和恒等式误差
```

若重算量不能在舍入误差内复现 B 的 reference，说明 C 没有调用完全相同的生产算子，测试无效。

## 11. A/B/C/D 实际运行方式

## 12. 必须先通过的测试

## 12.1 序列化 round-trip

构造非平凡本地状态，执行：

```text
对象 -> checkpoint -> 新对象
```

逐项比较：

- 背景物理 `f`；
- owned `Ex_face`；
- Beam 粒子顺序、`x/px/weight`；
- RNG state；
- injection remainder；
- 累计注入/出流能量；
- step/time/dt。

要求二进制 round-trip 逐位相同。

## 12.2 连续运行与 restart 一步等价

执行：

```text
路径 P：从状态 S 连续推进一步 -> P1
路径 R：S 写 checkpoint，重新启动，推进一步 -> R1
```

相同 MPI rank、线程数和编译参数下比较：

- `max|f_P1-f_R1|`；
- `max|Ex_face_P1-Ex_face_R1|`；
- Beam 粒子数、顺序、位置和动量；
- `JN/Jbeam/Jtotal`；
- 总粒子数和能量；
- nonlinear iteration 数和接受类型。

目标为逐位一致；若 MPI 归约顺序造成差异，至少应在 `1e-13` 相对尺度内且宏观诊断完全一致。

## 12.3 RNG/注入连续性

必须专门验证 restart 前后下一步：

- 注入宏粒子数相同；
- sampled crossing time 相同；
- 粒子初始动量相同；
- `N_in/Jbeam` 相同。

只比较已有粒子而不比较下一步注入，不能证明 Beam restart 正确。

## 12.4 MPI 失败测试

测试：

- 删除一个 rank 文件；
- 修改 manifest 的 MPI size；
- 修改网格参数；
- 截断一个 rank 文件；
- 破坏校验值。

要求所有 rank 一致退出并给出明确错误，不得出现 MPI collective 错位或 segmentation fault。

## 12.5 固定算子复现

B dump 后立即运行 C。要求：

```text
recomputed JN       == reference JN
recomputed JE       == reference JE
recomputed G*JE     == reference G*JE
recomputed R_FV     == reference R_FV
recomputed R_couple == reference R_couple
```

达到舍入误差后，C 才能用于区分空间离散误差。

## 12.6 dt/2 时间一致性

检查：

```text
time_D_final == time_A_final
```

并确认 D 的 Beam 注入量是两个真实半步注入量之和，而不是复制 A 的完整步注入。

## 13. 实施顺序

严格按以下顺序实施和提交，不要一次完成全部重构：

1. 增加 `RuntimeOptions` 和统一 `output-dir`，验证默认生产结果不变；
2. 增加 checkpoint 文件格式和 Species/field round-trip；
3. 增加 `BeamPersistentState`，完成 RNG/注入连续性测试；
4. 接入 `main.cpp` 的接受态 checkpoint 触发；
5. 实现 restart 路径，完成连续运行与 restart 一步等价测试；
6. 实现 `stop-after-steps`、`stop-time-fs`、`dt-scale` 和 `max-iters` 参数；
7. 原样提取生产固定中点算子评估函数，先验证生产短跑逐位不变；
8. 增加 `MidpointAuditState` dump；
9. 增加 `--operator-audit`，完成固定算子复现测试；
10. 短跑生成约 0.1 fs checkpoint，完整执行 A/B/C/D；
11. 通过后生成 3 fs checkpoint 并执行 A/B/C/D；
12. 再生成 6.5 fs checkpoint并执行 A/B/C/D；
13. 只有结论仍不充分时才继续到 12 fs。

每一步都必须先通过测试再进入下一步。第 7 步只是提取生产代码，不能顺便修改通量或求解算法。

## 14. 通过标准

基础设施通过必须同时满足：

- 默认参数下生产短跑结果不变；
- checkpoint round-trip 逐位一致；
- restart 一步与连续一步一致；
- Beam 下一步注入序列一致；
- 所有损坏 checkpoint 能 collective 安全失败；
- A/B/C/D 输出互不覆盖；
- `stop-after-steps` 只统计接受步；
- D 的最终物理时间与 A 相同；
- C 使用生产算子并复现 B 的 `JN/JE/G*JE`；
- operator-audit 不推进 `f/E/Beam/time`；
- checkpoint 和详细审计关闭时没有额外大数组或逐步 I/O 成本。

## 15. 用 A/B/C/D 判定问题

完成基础设施后按以下规则解释结果：

### 15.1 未收敛误差占主导

若 B 相比 A：

- `residual_E/residual_Jbkg` 明显下降；
- `R_couple` 和区域残差也同步显著下降；
- 宏观一步状态发生与残差下降一致的收敛变化；

则进入第 15.4 节，优先测试受保护 Aitken。

### 15.2 空间配对误差占主导

若：

- B 的中点残差下降；
- 但 C 在固定状态下仍得到几乎相同的 `JN-G*JE`；
- `R_couple` 对增加迭代不敏感；

则主要问题是生产空间离散配对，不应继续增加迭代或立即上 Anderson。

### 15.3 时间误差占主导

若 D 的误差相比 A/B 按明确阶数下降，而 C 的固定状态空间残差较小，则时间离散误差重要。

### 15.4 不允许的解释方式

不能只因为能量余额变小就认为修改正确。任何后续修复仍必须通过 12/15/18 fs 核心 `E/n/J/Beam` 基线，禁止用全局耗散或强 limiter 换取漂亮能量账。
