# 有风险性能优化与分级验证方案

## 1. 文档目的

本文档只处理在不主动改变 Vlasov-Ampere 物理模型、dual-u 离散、FCT、Beam
轨迹沉积和 Yee face Ampere 推进的前提下，仍可能显著提高运行速度、但必须经过
A/B 测试才能进入生产的优化。

当前可信生产基线为：

- `background-coupling-mode=dual-u`；
- 中点加速为 `none`；
- 原始时间步的 `0.5 dt` 最稳妥；
- `0.6 dt` 在 36 fs checkpoint 的 1000 步测试中全部严格接受；
- `0.6 dt` 平均约 `13.746` 次完整算子评估/步；
- `0.6 dt` 实测约 `1233.7 s/physical-fs`；
- 5 节点、每节点 16 MPI rank、每 rank 4 OpenMP 线程，总 MPI rank 为 80。

按该速度从 0 算到 120 fs 约需 41 小时。若要接近 24 小时，需要总加速约
`1.7x`。单一微优化通常不足以达到目标，必须优先减少完整中点算子评估次数，再降低
每次算子评估的成本。

本文档中的优化不得一次全部合入。必须按顺序一次只启用一项，并始终保留可运行的
baseline 路径。

## 2. 当前已经完成、不要重复做的低风险优化

当前代码已经具备：

1. dual-u 临时数组在一次外层中点求解内只分配一次，并跨 nonlinear iteration 复用；
2. 固定速度网格权重和能量差在一次外层求解开始时预计算；
3. Beam predictor 已移出中点迭代；
4. replay x/current 等固定状态审计不在普通生产迭代中执行；
5. stage5、区域分解和详细 accepted-state 诊断主要受
   `step_diagnostics_enabled_` 控制；
6. 普通生产步已经跳过 FCT 最坏点元数据的额外 MAXLOC/Bcast，以及非诊断步的
   accepted-state 最坏点扫描。

这些改动应作为所有后续 A/B 的共同起点，不应在风险优化中撤销。

## 3. 总体风险分级与执行顺序

| 顺序 | 优化 | 风险 | 预计收益 | 是否改变收敛方程 |
|---|---|---:|---:|---|
| 1 | 跨物理步中点初值预测 | 中 | `1.15x-1.7x` | 否，但改变有限迭代路径 |
| 2 | 跨物理步工作区复用与循环融合 | 中低 | `1.1x-1.35x` | 否 |
| 3 | 持久 OpenMP 区域与 SIMD 布局 | 中 | `1.1x-1.3x` | 否，但改变并行求和顺序 |
| 4 | MPI collective 打包/合并 | 中高 | `1.05x-1.25x` | 否，但改变归约顺序 |
| 5 | 面向计算节点的 CPU 指令集编译 | 中 | `1.05x-1.25x` | 否，但可能改变浮点结果 |
| 6 | 10 节点、保持 80 rank 的并行拓扑 | 运行风险 | 需实测 | 否 |
| 7 | 自适应 `0.5/0.6 dt` | 高 | 视后期收敛而定 | 改变时间网格 |

预期收益不能直接相乘。内存带宽、MPI 等待和中点迭代次数会互相制约。

以下内容不进入本轮：

- `-ffast-math`；
- 降低浮点精度；
- 放宽 E/J/f 收敛阈值；
- 降低 FCT 覆盖以换速度；
- 关闭 NaN/Inf、Beam 连续性或核心质量保护；
- 完整四维分布的 Anderson 线性组合；
- 为减少迭代而接受更多 soft-unconverged 状态。

## 4. 所有风险优化必须先增加的运行开关

不得通过反复修改源码常量来切换优化。先在 `src/runtime_options.h` 和
`src/runtime_options.cpp` 增加以下参数，并广播到所有 rank：

```text
--midpoint-initial-guess none|field-linear
--operator-workspace step|persistent
--operator-openmp baseline|persistent
--collective-mode baseline|packed
```

默认值必须全部保持 baseline：

```text
none, step, baseline, baseline
```

`src/main.cpp` 将这些选项传入 `VlasovAmpereMidpointSolver`。程序启动时由 rank 0
逐项打印最终模式。checkpoint manifest 记录这些模式，但不要因为模式不同而拒绝读取
物理状态；重启后使用本次命令指定的模式。

每个 accepted step 在 `performance_summary.result` 中至少记录：

```text
accepted_steps
strict_accept_count
soft_accept_count
total_midpoint_iterations
total_operator_evaluations
mean_iterations_per_step
mean_operator_evaluations_per_step
wall_seconds
wall_seconds_per_step
wall_seconds_per_physical_fs
```

没有这些字段的测试不能用于判断性能优化是否通过。

## 5. 优化一：跨物理步中点初值预测

### 5.1 目标

当前约 `13.7` 次完整算子评估/步是最大成本。预测只改变非线性迭代的初值，不改变
最终固定点方程。若平均迭代降至 10 次，理论收益约 `1.37x`；降至 8 次约
`1.71x`。

### 5.2 第一版只预测电场，不预测四维分布

不要直接保存和外推完整 `f_mid`，原因是：

- 内存和内存带宽成本很高；
- 线性外推可能制造负分布；
- 会改变 FCT active set，风险接近完整 Anderson；
- checkpoint 还要额外保存一份四维历史。

第一版在 `VlasovAmpereMidpointSolver` 中保存前两个严格接受物理步的
`E_mid` 或等价 `E_end`：

```text
E_pred = E_mid(n-1)
       + clamp(dt_n / dt_(n-1), 0, 1.25)
       * (E_mid(n-1) - E_mid(n-2))
```

然后做保护：

1. 周期唯一 face 保持别名一致；
2. 对每个 face 限制外推增量：

   ```text
   abs(E_pred - E_mid(n-1))
       <= 0.5 * max(E_scale, abs(E_mid(n-1)))
   ```

3. 任意值非有限时退回 `E_mid(n-1)`；
4. 上一步是 soft accept、失败重试、改变 `dt` 或 restart 后历史不足时，退回当前
   baseline 初值；
5. predictor 只生成第 0 次迭代的 `e_end`，之后仍执行现有普通 Picard 路径；
6. 不允许 predictor 自己额外调用一次完整算子评估；
7. 记录 `predictor_used`、初始场残差和最终迭代数。

修改文件：

- `src/vlasov_ampere_midpoint.h`：增加两层场历史和有效标志；
- `src/vlasov_ampere_midpoint.cpp`：增加 setter、历史提交/清空接口；
- `src/cylindrical_vlasov_midpoint.cpp`：仅替换中点迭代初值；
- `src/main.cpp`：只在 `state_advanced=1 && converged=1` 后提交历史；
- `src/runtime_options.h/.cpp`：增加运行开关；
- `src/checkpoint.h/.cpp`：第二阶段再考虑序列化 predictor 历史。

第一版不要求 checkpoint 保存 predictor 历史。restart 后前两步使用 baseline 初值，
从第三个严格接受步开始启用即可。这样 A/B 的第 1、2 步不能纳入稳态性能统计。

### 5.3 失败判据

出现任一项即回退：

- operator evaluations 比 baseline 增加；
- 任何 soft accept；
- FCT coverage、背景质量或能量账出现系统性退化；
- 相同物理时刻核心 Ex/n_bkg/J_bkg 超出第 11 节容差；
- predictor 导致额外 fallback 算子评估；
- 结果只能通过放宽收敛阈值才能接受。

## 6. 优化二：跨步工作区复用与循环融合

### 6.1 当前可继续优化的部分

`evaluate_production_midpoint_operator()` 当前仍在每个物理步创建大量 vector 和
`Species` 工作副本。虽然它们已跨中点迭代复用，但每步仍会分配、初始化和释放。

新增 `MidpointWorkspace`，由 solver 持有并按网格尺寸一次性 `resize()`：

```text
fx_low/fx_high/fx_final
fu_low/fu_high/fu_final
cu_low/cu_high/cu_final/cu_center
alpha arrays
candidate_mass/donor arrays
integrated J arrays
dual-u arrays
moment/energy temporary arrays
ghost send/recv buffers
```

每步只清零确实会被累加的区间。被每个循环元素完全覆盖的数组不得先 `fill(0)`。

必须满足：

1. workspace 只保存临时量，不保存物理状态；
2. resize 只在网格大小变化时发生；
3. fixed-state audit 与生产使用不同 workspace 或串行复用，不能并发；
4. 数组索引和尺寸加入 debug assert；
5. baseline 路径仍保留，便于 A/B；
6. 不把上一物理步的未覆盖数据带入本步。

### 6.2 循环融合

只融合遍历范围、权重和归约语义完全相同的扫描，例如：

- `min(f)`、NaN/Inf、质量、动能、动量局部统计；
- accepted-state 中只用于诊断的负债统计；
- 同一 `ix,j,k` 上的多个速度矩。

不能融合：

- 需要 halo exchange 前后不同状态的扫描；
- FCT limiter 决策与 limiter 应用；
- 先生成通量再消费通量的循环；
- 会改变共享 face 唯一 alpha 的循环。

验证时 baseline 与 workspace 版在相同初值下应达到：

- strict/soft 完全一致；
- iterations 和 operator evaluations 完全一致；
- Ex/J/n_bkg 的差异仅为舍入级；
- 无未初始化内存和跨步污染。

## 7. 优化三：持久 OpenMP 与 SIMD 友好布局

### 7.1 实施边界

只针对单次完整算子内连续执行的多个大循环建立一个持久：

```cpp
#pragma omp parallel
{
    #pragma omp for
    ...
    #pragma omp barrier
    #pragma omp for
    ...
}
```

不要跨 MPI 调用持有 OpenMP worker 区域，除非确认当前 MPICH 提供的线程级别与调用
方式兼容。第一版应在每次 MPI collective 前退出 parallel region。

优先处理：

1. x flux 构造；
2. u flux/dual-u correction；
3. FCT candidate 和 final flux；
4. moments 扫描。

速度维最内层保持连续内存。为固定权重数组增加：

```cpp
const double* __restrict
```

仅在确认不存在别名后使用。通过编译器向量化报告检查循环，而不是盲目增加
`omp simd`。

风险：

- reduction 顺序改变；
- 错误 barrier 导致读取未完成数组；
- false sharing；
- MPI 与 OpenMP 线程级别不兼容。

因此此项必须在 workspace 优化单独通过后再做。

## 8. 优化四：MPI collective 打包

### 8.1 只合并同语义、同位置的归约

`cylindrical_vlasov_midpoint.cpp` 仍有多组连续 `MPI_Allreduce`。第一版只打包：

- 同一代码位置；
- 同一 communicator；
- 同一数据类型；
- 同一归约操作；
- 后续使用前没有依赖；
- 所有 rank 无条件按相同顺序进入。

例如多个 `MPI_DOUBLE + MPI_SUM` 可先放入固定长度数组后一次归约；`MIN`、`MAX`、
`SUM` 不能打进同一次普通 Allreduce。

不能合并：

- 接受条件所需 MAX 与诊断 SUM；
- 可能被条件分支跳过的 collective；
- `MAXLOC/MINLOC` 与普通标量；
- Beam 和背景不同阶段的 collective；
- 会跨越 halo exchange 或状态更新的 collective。

### 8.2 必须增加 collective 序列审计

debug 模式下为每个 collective 分配固定 ID。每 100 步将本 rank 的 ID/hash 做
MIN/MAX 比较，确保所有 rank 序列相同。生产模式关闭该审计。

MPI 打包后允许末位求和差异，但必须满足：

- 无 MPI hang；
- strict/soft 和迭代数不退化；
- 质量、能量和核心波形容差通过；
- 真实 wall time 有至少 5% 收益，否则撤销复杂化。

## 9. 优化五：计算节点指令集与向量化编译

### 9.1 先确认 CPU

不要在登录节点直接用 `-march=native` 后假设计算节点兼容。先提交：

```bash
#!/bin/bash

#SBATCH -N 1
#SBATCH --ntasks-per-node=1
#SBATCH -c 1

#SBATCH -o cpu_probe_%j.out

yhrun -N 1 -n 1 lscpu
```

确认所有计算节点属于同一 CPU 型号后，使用 GCC 对应的显式 `-march=<cpu>`。只有在
编译也发生于同型号计算节点时才使用 `-march=native`。

推荐先测试：

```text
-O3 -march=<confirmed-cpu> -mtune=<confirmed-cpu>
```

不得加入：

```text
-ffast-math
-Ofast
-fassociative-math
-funsafe-math-optimizations
```

### 9.2 向量化报告

增加仅用于编译审计的选项：

```text
-fopt-info-vec-optimized
-fopt-info-vec-missed
```

重点检查 x/u/FCT/dual-u 大循环。报告本身不是性能通过条件，必须看 wall time。

## 10. 优化六：10 节点但保持 80 MPI rank

checkpoint 第一版要求相同 MPI rank 数，因此 10 节点生产应使用：

```text
10 nodes
8 MPI ranks/node
8 OpenMP threads/rank
80 MPI ranks total
640 physical cores total
```

而不是 160 rank。这样已有 80-rank checkpoint 可直接重启。

风险是每 rank 的内存带宽扩展、OpenMP scaling 和跨节点 halo/collective 开销可能抵消
核心数增加，因此必须与 5 节点 `16x4` 做同一 checkpoint、同一 500 步 A/B。

## 11. 统一验收指标

### 11.1 性能指标

每个作业必须记录：

```text
wall_seconds
accepted_steps
physical_time_advanced_fs
operator_evaluations
midpoint_iterations
strict_accept_count
soft_accept_count
```

派生：

```text
wall/step
wall/operator_evaluation
wall/physical-fs
operator_evaluations/step
iterations/step
```

只比较 `1000步用了多久` 不够，因为时间步和算子评估数可能不同。

### 11.2 数值指标

从同一 checkpoint 出发，在同一最终物理时刻比较：

- `Ex_face` 核心区相对 L2、Linf、峰值和主峰位置；
- `n_bkg` 核心区相对 L2；
- `J_bkg` 和总 J；
- 总能量账、背景质量；
- FCT active fraction、min alpha；
- strict/soft；
- Beam 注入/出流累计量与连续性。

对于只改变内存管理的优化，目标是舍入级一致。对于 predictor、MPI 归约顺序和
CPU 指令集优化，不要求 bitwise hash 一致，但宏观误差必须不高于同一 `dt` 的时间
离散误差。

### 11.3 三层测试

1. **100 步预检**：排除崩溃、MPI hang、额外算子评估和明显回归；
2. **1000 步性能测试**：统计稳态 wall/operator 和平均迭代；
3. **36--40 fs 物理复验**：检查后期非线性波包、FCT 和能量。

100 步测试的前 10 步作为 warm-up，不计入 predictor 性能均值。

## 13. 运行命令

以下命令假定 36 fs checkpoint 保存的是 `0.5 * dt_original`，因此
`--dt-scale 1.20` 对应 `0.6 * dt_original`。必须先从 `restart_audit.dat` 或
checkpoint manifest 核对保存的 `dt`；若 checkpoint 本身已保存 `0.6 dt`，则改用
`--dt-scale 1.0`。

### 13.1 baseline 1000 步

```bash
#!/bin/bash
#SBATCH -p xyfree
#SBATCH -N 5
#SBATCH --ntasks-per-node=16
#SBATCH -c 4
#SBATCH -J perf_base
#SBATCH -o perf_base_%j.out
#SBATCH -e perf_base_%j.err

export OMP_NUM_THREADS=$SLURM_CPUS_PER_TASK
export OMP_PLACES=cores
export OMP_PROC_BIND=close

module purge
module load mpi/mpich/4.1.2-gcc-11.4.0-ch4

cd /HOME/sztu_lbju/sztu_lbju_1/HDD_POOL/Chendong/FokkerPlanckEquationSolver
CHECKPOINT_36="/ABSOLUTE/PATH/TO/36FS_CHECKPOINT"
OUT="./output/perf_risk/base_1000"
mkdir -p "$OUT"

TIMEFORMAT=$'real_s=%R\nuser_s=%U\nsys_s=%S'
{ time yhrun --cpu-bind=cores stdbuf -oL -eL \
  ./build_perf_base/fp_solver \
  --restart "$CHECKPOINT_36" \
  --background-coupling-mode dual-u \
  --dt-scale 1.20 \
  --midpoint-acceleration none \
  --midpoint-max-iters 40 \
  --stop-after-steps 1000 \
  --diagnostic-level 1 \
  --beam-ledger-mode summary \
  --output-dir "$OUT" \
  --overwrite-output \
  > "$OUT/run.out" 2> "$OUT/run.err"; } 2> "$OUT/timing.txt"
```

## 14. 36--40 fs 物理复验

只有某项 1000 步测试同时提高性能且没有数值退化，才从同一 36 fs checkpoint 跑到
40 fs。命令沿用对应模式，将：

```text
--stop-after-steps 1000
```

替换为：

```text
--stop-time-fs 40
--checkpoint-times 40
```

输出目录追加 `_to_40fs`。baseline 也必须跑到相同物理时刻，不能拿不同 `dt`、不同
终止步数的结果直接比较。

重点验收此前约 36 fs 后开始出现的：

- `1.5-2.3 um` 主波包峰值与相位；
- `2.5-5.5 um` 后部调制；
- 背景密度是否被额外平滑；
- FCT active set 是否扩大；
- 能量账是否超过 baseline；
- strict convergence 是否保持。

## 15. 最终采用规则

每项优化必须独立满足：

1. 100 步预检无崩溃、hang、soft accept；
2. 1000 步全部严格接受；
3. operator evaluations/step 不增加；
4. wall/physical-fs 至少改善 5%；
5. 36--40 fs 宏观波形不劣于 baseline；
6. 背景质量、能量、Beam 连续性和 FCT 不出现系统性退化；
7. checkpoint/restart 仍能在 80 rank 下工作。

未达到 5% 的复杂优化即使数值正确也不合入生产，因为维护成本和回归风险大于收益。

推荐最终顺序：

```text
baseline重新测量
  -> field-only跨步预测
  -> persistent workspace
  -> persistent OpenMP/SIMD
  -> packed collectives
  -> CPU指令集构建
  -> 10节点80-rank拓扑
  -> 36--40 fs物理复验
  -> 分段生产
```

只有前一项通过，后一项才允许叠加。任何一步失败，都回到最近通过版本，不继续在失败
实现上增加补丁。
