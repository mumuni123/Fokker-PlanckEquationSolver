# 第 12 节测试：编译、运行与最短执行流程

本文档只说明测试命令和执行顺序。核心原则是：

- **12.1–12.4 是进入第 11 节前的基础设施短测，不需要跑到 3 fs 或 6.5 fs。**
- **6.5 fs checkpoint 只在第 11.1 节生成一次。**
- 12.5 与 12.6 分别随第 11.4 节 C 和第 11.5 节 D 验收，不是第 11 节之前的前置长跑。
- 独立测试默认使用单节点少量 MPI rank；正式 A/B/C/D 才使用生产作业规模。

原版本把“生成 6.5 fs 共享 checkpoint”放进了 12.3，并默认让所有测试使用 80 rank/10 节点，这是不必要的，也会把几分钟的基础设施测试错误地变成长跑。本版已纠正。

---

## 0. 编译一次

不要在每项测试前删除整个 build 目录。首次配置后增量编译即可：

```bash
cmake -S . -B build_checkpoint_tests \
  -DCMAKE_CXX_COMPILER=mpicxx \
  -DFP_BUILD_CHECKPOINT_TESTS=ON

cmake --build build_checkpoint_tests -j 16 \
  --target fp_solver checkpoint_roundtrip_test \
           restart_one_step_equivalence_test \
           beam_rng_injection_continuity_test \
           checkpoint_failure_safety_test \
           beam_dt_half_time_consistency_test \
           fixed_midpoint_operator_audit_test
```

设置两套运行规模：

```bash
BIN="$(pwd)/build_checkpoint_tests"
TEST_ROOT="$(pwd)/output/checkpoint_preflight"
mkdir -p "$TEST_ROOT"

# 12.1--12.4：单节点短测。nx 必须能被 NP_TEST 整除。
NP_TEST=4
RUN_TEST="srun -N 1 -n ${NP_TEST} --cpu-bind=cores"

# 第 11 节正式 A/B/C/D 才使用生产规模。
NP_PROD=80
RUN_PROD="srun -N 10 -n ${NP_PROD} --cpu-bind=cores"
```

如集群使用 `yhrun`、`mpirun` 或其他启动器，只替换 `RUN_TEST/RUN_PROD`。不要改变测试本身的参数。

预计耗时：

| 项目 | 物理推进 | 典型耗时 |
|---|---:|---:|
| 12.1 | 0 步 | 数秒至 1 分钟 |
| 12.2 | 生产背景/场内核各推进 1 步 | 约 1–5 分钟，依机器而定 |
| 12.3 | Beam 注入短测试，通常 1–数步 | 数秒至 2 分钟 |
| 12.4 | 只读损坏 checkpoint，0 步 | 合计约 1–5 分钟 |
| 第 11.1 | 连续推进到 6.5 fs | 唯一一次长跑 |
| 12.5/12.6 | 复用第 11.1 checkpoint | 数个生产步 |

## 阶段 A：第 11 节之前必须完成的短测

## 12.1 序列化 round-trip

该测试构造一个非平凡内存状态，立即执行“写 checkpoint → 新对象读取”，不推进物理时间。

```bash
rm -rf "$TEST_ROOT/12.1"
mkdir -p "$TEST_ROOT/12.1"

(
  cd "$TEST_ROOT/12.1"
  $RUN_TEST "$BIN/checkpoint_roundtrip_test" \
    > test.out 2> test.err
)

cat "$TEST_ROOT/12.1/test.out"
cat "$TEST_ROOT/12.1/test.err"
```

验收：

```text
checkpoint_roundtrip f_difference=0 Ex_face_difference=0 \
  beam_particle_difference=0 persistent_state_match=1 \
  control_state_match=1 status=PASS
```

还必须确认测试源码逐项比较：

- 背景物理 `f`；
- owned `Ex_face`；
- Beam 粒子顺序和 `x/px/weight`；
- 完整 `BeamPersistentState`，包括 RNG、注入余数和累计量；
- `step/time/dt`。

本测试生成的小型有效 checkpoint 位于：

```bash
SMALL_CHECKPOINT="$TEST_ROOT/12.1/checkpoint_roundtrip_tmp"
```

12.4 直接复制这个 checkpoint，不需要先跑 6.5 fs。

## 12.2 连续运行与 restart 一步等价

```bash
rm -rf "$TEST_ROOT/12.2"
mkdir -p "$TEST_ROOT/12.2"

(
  cd "$TEST_ROOT/12.2"
  $RUN_TEST "$BIN/restart_one_step_equivalence_test" \
    > test.out 2> test.err
)

cat "$TEST_ROOT/12.2/test.out"
cat "$TEST_ROOT/12.2/test.err"
```

验收：

```text
restart_one_step_equivalence ... JN_difference=... Jbeam_difference=... \
  Jtotal_difference=... total_energy_difference=... status=PASS
```

该测试现在保持 Beam 开启，并比较背景 `f`、`Ex_face`、Beam 粒子顺序及
`x/px/weight`、`JN/Jbeam/Jtotal`、背景/Beam 总粒子数、总能量、背景/Beam
动能变化、非线性迭代次数和接受类型。12.3 仍单独验证 RNG 与下一次注入序列。

## 12.3 RNG / Beam 注入连续性

独立自动测试会先生成包含非零注入余数和已推进粒子的 checkpoint，随后比较
“不重启继续下一步”与“恢复 checkpoint 后推进下一步”。它逐位比较新增粒子
的数目、位置（包含 sampled crossing time 的结果）、动量、`N_in`、`J_beam`、
密度和 charge-conserving face current：

```bash
rm -rf "$TEST_ROOT/12.3"
mkdir -p "$TEST_ROOT/12.3"
(
  cd "$TEST_ROOT/12.3"
  $RUN_TEST "$BIN/beam_rng_injection_continuity_test" > test.out 2> test.err
)
cat "$TEST_ROOT/12.3/test.out"
cat "$TEST_ROOT/12.3/test.err"
```

预期 `max_difference=0` 且 `status=PASS`。这项是 12.3 的正式验收；下面
的 A/D 是不同时间步划分下的生产诊断，不能要求随机 crossing 序列逐粒子相同。

## 12.3 生产 A/D 诊断比较

### 不再生成 6.5 fs checkpoint

12.3 只验证 checkpoint 前后“下一次 Beam 注入”是否完全相同。它不需要已发展波形，也不需要跑到 6.5 fs。

原命令中以下流程应删除：

```text
fp_solver --checkpoint-times 6.5 --stop-time-fs 6.5
```

原来的 A 与两个 `dt/2` 步比较也不是 RNG restart 测试，因为改变 `dt` 后 crossing time 序列和注入分组本来就可能不同；那属于 12.6。

### 自动测试覆盖

`beam_rng_injection_continuity_test` 已实现下列检查：

1. 建立相同的非平凡 Beam 初态；
2. 路径 P 不经过序列化，执行下一次真实 `begin_step/inject/push/deposit/finalize_current`；
3. 路径 R 先写入并读取 checkpoint，再以相同 `dt/time/field` 执行同一次 Beam 操作；
4. 逐项比较：
   - 注入宏粒子数；
   - 每个新粒子的 `x/px/weight`；
   - sampled crossing time 或等价的 `injected_push_dt`；
   - `injection_remainder` 和更新后的 RNG state；
   - `N_in`、`Jbeam_face`、左右出流量；
   - 更新后的全部 Beam 粒子顺序。

验收必须是自动 `status=PASS`。不能仅靠：

```bash
grep "N_in|J_beam|cross|injected" ...
```

因为普通生产日志未必输出每个 crossing time，而且手工 grep 无法证明粒子顺序和 RNG state 逐位一致。

## 12.4 MPI 一致失败测试

优先运行自动化 collective 安全测试。它逐一覆盖缺少 rank 文件、MPI size
不匹配、网格参数不匹配、rank 文件截断和 manifest checksum 损坏：

```bash
rm -rf "$TEST_ROOT/12.4"
mkdir -p "$TEST_ROOT/12.4"
(
  cd "$TEST_ROOT/12.4"
  $RUN_TEST "$BIN/checkpoint_failure_safety_test" > test.out 2> test.err
)
cat "$TEST_ROOT/12.4/test.out"
cat "$TEST_ROOT/12.4/test.err"
```

五个案例都必须输出 `collective_failure=1 status=PASS`。下方的 `fp_solver`
手工案例保留为端到端启动器诊断，不替代自动测试。

所有破坏操作只针对 12.1 生成的 checkpoint 副本。每个案例只执行初始化和读取，应该迅速失败，绝不能推进一个物理步。

```bash
CASE_ROOT="$TEST_ROOT/12.4_cases"
rm -rf "$CASE_ROOT"
mkdir -p "$CASE_ROOT"
```

- 不出现 MPI collective 错位或 `Message truncated`；
- 不产生任何已接受物理步。

## 阶段 B：第 11 节及其伴随验收

只有 12.1–12.4 通过后，才开始以下流程。

## 11.1 唯一一次 6.5 fs checkpoint 长跑

```bash
rm -rf output/checkpoint_generation

$RUN_PROD "$BIN/fp_solver" \
  --checkpoint-times 3,6.5 \
  --stop-time-fs 6.5 \
  --diagnostic-level 1 \
  --output-dir output/checkpoint_generation \
  > output/checkpoint_generation.out \
  2> output/checkpoint_generation.err
```

记录真实生成目录：

```bash
CHECKPOINT_3FS=output/checkpoint_generation/checkpoints/t_03.*
CHECKPOINT_65FS=output/checkpoint_generation/checkpoints/t_06.5*
```

通配符只用于人工定位；正式命令应替换为唯一的完整目录名。

## 11.2 A 与 11.3 B

```bash
rm -rf output/probe_06.5fs/A output/probe_06.5fs/B

$RUN_PROD "$BIN/fp_solver" --restart "$CHECKPOINT_65FS" \
  --stop-after-steps 1 --midpoint-max-iters 40 --dt-scale 1 \
  --diagnostic-level 2 --dump-final-midpoint \
  --output-dir output/probe_06.5fs/A \
  > output/probe_06.5fs_A.out 2> output/probe_06.5fs_A.err

$RUN_PROD "$BIN/fp_solver" --restart "$CHECKPOINT_65FS" \
  --stop-after-steps 1 --midpoint-max-iters 200 --dt-scale 1 \
  --diagnostic-level 2 --dump-final-midpoint \
  --output-dir output/probe_06.5fs/B \
  > output/probe_06.5fs_B.out 2> output/probe_06.5fs_B.err
```

`--diagnostic-level 2` 会在 A/B 目录逐步写入 `step_diagnostics.dat`、
`accepted_coupling_residual_by_region.dat` 和 `midpoint_iteration_residuals.dat`。
B 的最后一个文件记录第 1 次、每第 10 次及最后一次 Picard 迭代的
`r_E/r_J_bkg`，以及相邻记录之间的收缩率；即使该探针步失败也会保留已执行迭代的历史。

## 12.5：随 11.4 C 验收固定算子复现

```bash
rm -rf output/probe_06.5fs/C

$RUN_PROD "$BIN/fp_solver" \
  --operator-audit output/probe_06.5fs/B/final_midpoint \
  --diagnostic-level 2 \
  --output-dir output/probe_06.5fs/C \
  > output/probe_06.5fs_C.out 2> output/probe_06.5fs_C.err

cat output/probe_06.5fs/C/fixed_midpoint_operator_audit.result
```

验收：

- `recomputed JN == reference JN`；
- `recomputed JE == reference JE`；
- `recomputed G*JE == reference G*JE`；
- 周期接缝的 `JN(0/L)`、`G*JE(0/L)` 及两侧 `JN-G*JE` 与 B dump 逐项达到舍入误差；
- `R_FV/R_couple` 与 B dump 一致；
- 保存的 `beam_front_ix/wave_core_end_m` 与 C 重放布局一致；其中 C 直接恢复 B
  dump 的 `beam_front_ix`，不得从固定 Beam 电流重新推断区域前沿；
- 六区域三项恒等式误差达到舍入误差量级。

`final_midpoint` 的二进制格式现为 `FPMIDPT5`；旧 dump 不包含完整动态区域布局或周期接缝 face 审计，必须重新运行 B。

12.5 失败时，C 无效，不能据此判断空间离散误差。

## 12.6：随 11.5 D 验收 dt/2

复用 11.2 的 A，只新增 D，不要重复运行 A：

```bash
rm -rf output/probe_06.5fs/D

$RUN_PROD "$BIN/fp_solver" --restart "$CHECKPOINT_65FS" \
  --stop-after-steps 2 --midpoint-max-iters 200 --dt-scale 0.5 \
  --diagnostic-level 2 \
  --beam-ledger-reference output/probe_06.5fs/A/beam_dt_half_time_consistency.result \
  --output-dir output/probe_06.5fs/D \
  > output/probe_06.5fs_D.out 2> output/probe_06.5fs_D.err
```

验收：

```text
time_D_final == time_A_final
N_in_A == N_in_D1 + N_in_D2
```

达到浮点舍入误差，并确认：

- A 的 `beam_dt_half_time_consistency.result` 记录完整步的 `N_in_total` 与注入电流时间积分；
- D 的 `beam_half_step_ledger.dat` 必须有两个已接受子步行，分别给出 `N_in/N_out`、注入/出流能量及边界电流积分；
- D 的 `beam_dt_half_time_consistency.result` 中必须分别有 `substep_1_*` 与
  `substep_2_*` 台账，且 `reference_comparison_pass=1`，
  `N_in_A_minus_D_sum` 与 `injected_current_impulse_A_minus_D_sum` 为舍入误差量级。

- D 确实执行两个真实 `dt/2` 接受步；
- 每个半步独立执行 Beam crossing-time 注入；
- D 的总注入量等于两个真实半步注入量之和；
- 没有先按完整 `dt` 注入后再拆分 pusher。

## 最终执行顺序

```text
编译一次
  ↓
12.1 round-trip（0 步）
  ↓
12.2 背景/场 restart 一步等价（1+1 次单步调用）
  ↓
12.3 Beam RNG/注入独立短测（当前需补 target）
  ↓
12.4 五个损坏 checkpoint 读取测试（0 步）
  ↓
可选 fixed-operator 合成状态冒烟
  ↓
11.1 唯一一次跑到 6.5 fs，生成 3/6.5 fs checkpoint
  ↓
11.2 A → 11.3 B → 11.4 C/12.5 → 11.5 D/12.6
```

第 11 节前的硬门槛是 12.1–12.4。12.5 和 12.6 必须依赖第 11 节产生的真实 B/C/D 状态，因此不能提前要求完成。
