# 第 11 节两类补充实验修正与执行方案

## 1. 目的与边界

本文档用于修正并重跑两类实验：

1. 分别只加密 `x`、`u_parallel`、`u_perp`，识别 `J_N-G*J_E` 的方向误差；
2. 在生产 high-order x 面通量的构造源头使用能量链式速度候选，完成共同速度 A/B，而不是事后做 `v_E/v_x` 缩放。

修改仅服务测试。不得改变生产求解器默认 FCT、保护、Beam、Yee face Ampere 或正式长跑路径。

## 2. 当前结果为什么无效

### 2.1 单档测试提前失败

当前 9 个分方向结果全部为：

```text
passes=0
current_L1/L2/Linf=0
work_L1/L2/Linf=0
```

这些零不是严格闭合，而是 bundle 在形成有效 high-order 电流矩前失败返回，测试把默认零数组写进了结果。

测试设置了：

```cpp
options.fct_enabled = false;
```

却没有开启已有的 no-FCT 测试专用有限负债许可。生产内核仍先检查 low-order 候选态；候选出现有限负值后，会在最终 high-order 电流矩组装前返回。

### 2.2 汇总器假通过

`tests/background_coupling_directional_grid_audit.cpp` 当前只用：

```cpp
passes = fct_consistent && fixed_other_grids;
```

它没有检查输入 `passes`、状态是否推进、结果是否有限、残差是否为默认零、是否单调下降。因此三个 audit 的 `passes=1` 只证明配置相同，不证明收敛。

### 2.3 x 加密混入时间误差

当前 `dt=0.025*dx/c`。`Nx` 加倍时 `dt` 同时减半，得到的是空间与时间联合收敛，不是纯 x 收敛。

### 2.4 第二类实验尚无结果

已有 `tests/background_coupling_common_speed_flux_test.cpp`，但根目录没有 `background_coupling_common_speed_flux.result`。该测试同样关闭 FCT，也会遇到上述门禁。

## 3. 总原则

1. 只放宽测试专用 no-FCT 路径，生产默认保持不变；
2. NaN/Inf、数组越界、MPI 错误仍硬失败；
3. 允许有限负债只是为了完成 raw high-order 算子审计；
4. 区分“实验有效完成”与“科学假设成立”；
5. 未推进状态、默认零和旧文件不得进入收敛阶计算；
6. 每次只改变一个网格方向，并固定物理 `dt`；
7. 共同速度必须从源头重新生成 high-order x 通量。

## 4. 修正共享测试入口

### 4.1 修改文件

```text
tests/background_coupling_test_support.h
```

### 4.2 扩展 `BundleOptions`

新增：

```cpp
bool allow_finite_negative_debt;
```

默认必须为 `false`。在 `evaluate_bundle()` 中连接：

```cpp
solver.set_allow_finite_negative_debt_for_test(
    options.allow_finite_negative_debt);
```

只有本文指定的 no-FCT 实验把它设为 `true`。

### 4.3 拆分失败与有限性

当前：

```cpp
bundle.finite = evaluation.failed ? 0 : 1;
```

错误地把“保护失败”和“NaN/Inf”混为一类。改为独立记录：

```cpp
int operator_failed;
int outputs_finite;
```

- `operator_failed` 记录 `evaluation.failed`；
- `outputs_finite` 独立扫描状态、场、`fx_high`、`fu_center`、`jn_high`、`je_center`、`gstar_je_center`；
- 旧 `finite` 若需保留，应等于 `outputs_finite`，不能等于 `!failed`。

## 5. 扩充 bundle 失败诊断

### 5.1 修改文件

```text
src/vlasov_ampere_midpoint.h
src/vlasov_ampere_midpoint.cpp
```

在 `BackgroundCouplingFluxBundle` 增加：

```cpp
int operator_failed;
int outputs_finite;
int failure_reason;
int failure_iteration;
int failure_substep;
double low_order_candidate_min;
long long low_order_negative_count;
double low_order_negative_mass;
double final_candidate_min;
```

在 `evaluate_background_coupling_flux_bundle()` 中从现有 evaluation/result 逐项复制，不改推进公式。`final_candidate_min` 若没有现成字段，应扫描物理单元并用 MPI `MIN` 汇总。

只有满足以下条件才允许计算范数：

```cpp
state_advanced == 1
operator_failed == 0
outputs_finite == 1
所有必需数组尺寸正确
```

## 6. 统一单档结果格式

每个单档结果至少输出：

```text
state_advanced=
operator_failed=
outputs_finite=
failure_reason=
failure_iteration=
failure_substep=
low_order_candidate_min=
low_order_negative_count=
low_order_negative_mass=
final_candidate_min=
current_L1/L2/Linf=
work_L1/L2/Linf=
audit_valid=
passes=
```

有效性定义：

```cpp
audit_valid = state_advanced && !operator_failed && outputs_finite &&
              arrays_have_expected_size &&
              isfinite(current_L2) && isfinite(work_L2) &&
              current_L2 > 0.0 && work_L2 > 0.0;
```

制造态包含非零速度扰动和非零场，因此精确零应视为无效哨兵。失败时范数写 `nan`，不能写 0。单档 `passes` 等于 `audit_valid`。

## 7. 实验一：分方向网格加密

### 7.1 修正单档测试入口

修改：

```text
tests/background_coupling_directional_grid_test.cpp
```

设置：

```cpp
BackgroundCouplingTest::BundleOptions options;
options.fct_enabled = false;
options.allow_finite_negative_debt = true;
```

该选项只能绕过“有限负值使 no-FCT 审计提前返回”，不能绕过 NaN/Inf。计算范数前先验证 bundle；无效时写真实失败诊断、`nan`、`passes=0` 并返回非零。

### 7.2 x 三档固定 `dt`

网格保持：

```text
Nx=1000,2000,4000
Nu=96
Nuperp=64
```

三档统一使用：

```cpp
dt_x = 0.025 * (Param::Lx / 4000.0) / Const::c;
```

结果增加：

```text
dt_policy=fixed_from_finest_x
dt_reference_nx=4000
```

### 7.3 `u_parallel` 三档固定 `dt`

保持：

```text
Nx=2000, Nuperp=64, Nu=48,96,192
```

先按最细 `Nu=192` 验证速度 CFL，再让三档使用同一安全 `dt`。不得随 `Nu` 改变时间步。

### 7.4 `u_perp` 三档固定 `dt`

保持：

```text
Nx=2000, Nu=96, Nuperp=32,64,128
```

按最细 `Nuperp=128` 确定共同安全 `dt`，三档一致。

### 7.5 修正汇总器

修改：

```text
tests/background_coupling_directional_grid_audit.cpp
```

`read_result()` 必须读取并要求：

```text
passes, audit_valid, state_advanced, operator_failed,
outputs_finite, dt, current_L2, work_L2,
fct_enabled, fct_active
```

新增：

```cpp
inputs_valid = 三档 passes/audit_valid 均为 1;
dt_fixed = 三档 dt 在 64*epsilon 相对范围内相同;
finite_nonzero = 六个 L2 均有限且大于 0;
monotone = current 和 work 均 coarse > base > fine;
```

最终必须是：

```cpp
passes = inputs_valid && fixed_other_grids && fct_consistent &&
         dt_fixed && finite_nonzero && monotone;
```

输出：

```text
audit_inputs_valid=
configuration_valid=
dt_fixed=
current_L2_monotone=
work_L2_monotone=
asymptotic_order_established=
passes=
```

观测阶继续输出。最后两档阶数若低于约 0.5，令 `asymptotic_order_established=0`；不得只因配置正确而通过。

### 7.6 结果解释

- 仅 x 收敛：重点检查 x 面重构与面/cell 配对；
- 仅 `u_parallel` 收敛：重点检查 u 功矩与链式速度；
- 仅 `u_perp` 收敛：重点检查圆柱权重和横向速度积分；
- 三者均收敛：比较生产网格附近的方向敏感度，不能依赖全面加密；
- 某方向不收敛：存在该方向不随网格消失的算子不一致；
- 全部不收敛：优先检查 `J_N` 与 `G*J_E` 是否来自不同通量未知量。

## 8. 实验二：共同速度源头重构 A/B

### 8.1 修正入口

修改：

```text
tests/background_coupling_common_speed_flux_test.cpp
```

两组均设置：

```cpp
options.fct_enabled = false;
options.allow_finite_negative_debt = true;
```

唯一差异为：

```cpp
energy_consistent_x_high_velocity=false; // analytic
energy_consistent_x_high_velocity=true;  // common
```

不得同时改变 `dt`、状态、场、重构阶数、u 通量或 Ampere 算子。

### 8.2 验证 A/B 控制量

必须输出并检查：

```text
fx_high_difference_relative_Linf > roundoff
fu_center_difference_relative_Linf <= roundoff
GstarJE_center_difference_relative_Linf <= roundoff
state_hash_equal=1
field_hash_equal=1
only_x_high_branch_changed=1
```

只有这些条件成立，才证明实验确实只改变了 x high 速度分支。

### 8.3 禁止事后缩放

不得使用：

```cpp
flux_common = flux_analytic * vE / vx;
```

共同速度要在 high-order x 通量形成前参与左右状态传播、面方向判定和最终面物理通量。若 MUSCL/CTU 把重构与乘速度分开，传播方向和最终乘法都必须使用同一个候选速度。

### 8.4 增加样本

至少测试：

```text
E0=+1000, phase=0
E0=-1000, phase=0
E0=+1000, phase=7*2*pi/Nx
E0=-1000, phase=7*2*pi/Nx
```

每组输出 analytic/common 的 current L1/L2/Linf、work L1/L2/Linf、比值和全局带符号残差。科学判断以局部范数为主，不能依赖全局正负抵消。

### 8.5 区分有效完成与假设成立

结果必须包含：

```text
operator_valid=
experiment_control_valid=
common_speed_improves_all_cases=
common_speed_worst_L2_ratio=
hypothesis_pass=
passes=
```

定义：

```cpp
passes = operator_valid && experiment_control_valid;
hypothesis_pass = passes && common_speed_improves_all_cases;
return passes ? 0 : 1;
```

`passes=1,hypothesis_pass=0` 是成功完成的否定实验，不应中断整个测试流程。

## 10. 执行顺序

### 10.1 单个基准预检

先只运行 `background_coupling_x_refinement`。必须得到：

```text
state_advanced=1
operator_failed=0
outputs_finite=1
audit_valid=1
passes=1
current_L2>0
work_L2>0
```

若失败，先根据 `failure_reason` 和 low-order 诊断修测试入口，不得批量运行。

### 10.2 三组分方向测试

依次运行 x、`u_parallel`、`u_perp` 的 coarse/base/fine。每档立即检查 `passes=1`；任一失败，不运行该组汇总器。

### 10.3 三个汇总审计

对应三档都有效后再运行 audit，并先检查 `audit_inputs_valid=1`、`dt_fixed=1`，然后解释收敛阶。

### 10.4 共同速度 A/B

最后运行共同速度测试。先判断 `passes`，再判断 `hypothesis_pass`。

## 11. 防止旧结果污染

1. 优先为本轮设置独立输出目录；
2. 若仍写 `output`，运行前按完整文件名删除本轮预期旧文件；
3. 检查新文件修改时间晚于本轮开始；
4. 汇总器必须拒绝缺失文件；
5. 可写 `run_id` 和配置摘要，但不得依赖测试机存在 Git。

## 12. 验收条件

### 12.1 分方向实验

- 9 个单档全部有效；
- 结果有限且不是默认零；
- 每组只改变一个方向；
- 每组三档使用同一 `dt`；
- FCT 均关闭且未激活；
- 无效输入不能再让 audit 假通过；
- 给出单调性和两段观测阶。

### 12.2 共同速度实验

- analytic/common 都生成有效 bundle；
- 除 x high 速度选择外其余控制量一致；
- 确认 high-order x 通量从源头重建；
- 正负场和相位样本完整；
- 报告局部范数；
- `passes` 与 `hypothesis_pass` 分开。

## 13. 结果后的决策

若共同速度在所有样本中稳定降低局部残差，才进入独立生产候选分支和 checkpoint A/B；不能直接覆盖生产路径。

若无改善或恶化，禁止继续简单统一 `v_x=v_E`。这说明问题不是单个 cell 速度可以消除，需要共同面状态、共同通量未知量或联合约束。

若方向误差都可收敛，应比较当前生产网格附近的方向敏感度，而不是全面扩大网格。若某方向不收敛，优先审计该方向的权重、面位置、时间层和通量变量。

## 14. 禁止事项

本轮不得：

- 改生产 FCT 和负分布保护默认值；
- 改 Beam、Yee Ampere 或周期拓扑；
- 做 Poisson 投影或零模扣除；
- 构造只为能量账服务的独立修正电流；
- 把无效值写成 0；
- 同时改变多个网格方向或 `dt`；
- 在 A/B 证据前把 test-only 共同速度用于长跑。
